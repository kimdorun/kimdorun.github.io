HWPX 공문서·공모전 서식 규격 점검기

한글(.hwpx) 파일을 올리면 표준 압축 규격, 섹션·문단·표 개수, 글자 수, 이미지 용량, 제출 직전에 놓치기 쉬운 자리표시자까지 한 번에 확인합니다. 파일은 서버로 전송되지 않고 내 기기 브라우저에서만 분석됩니다.

.hwpx는 어떤 파일인가

한글 2014부터 쓰이는 .hwpx는 문서를 여러 XML 파일로 나눠 담은 OWPML 형식입니다. 겉모습은 ZIP 압축 파일과 같아서, 열어 보면 mimetype, version.xml, Contents/header.xml, Contents/section0.xml, BinData/ 같은 항목이 들어 있습니다. mimetype 값은 반드시 application/hwp+zip이어야 하고, 본문은 Contents/section*.xml에 문단(hp:p)과 표(hp:tbl)로 저장됩니다.

이 구조 덕분에 문서를 열지 않고도 분량과 구성을 정확히 셀 수 있습니다. 이 점검기는 ZIP의 중앙 디렉터리와 로컬 헤더를 직접 읽고, 압축을 브라우저 내장 DecompressionStream('deflate-raw')으로 풀어 XML을 분석합니다. 외부 CDN 라이브러리를 쓰지 않으므로 오프라인에서도, 보안 정책이 엄격한 브라우저에서도 동작합니다.

왜 제출 전에 점검해야 하나

공모전·공공기관 제출에서 반려되는 이유는 내용보다 형식인 경우가 많습니다. 대표적인 네 가지를 이 도구가 확인합니다.

  • 글자 수 초과 — 공고는 “공백 제외 2,000자 이내”처럼 기준을 명시합니다. 한글 화면의 글자 수와 공고 기준이 다르면 초과가 발생합니다.
  • 서식·표 누락 — 지정 양식의 표를 지우거나 새 문서에 옮겨 적으면 항목이 빠집니다. 표 개수와 문단 수로 구조가 유지됐는지 봅니다.
  • 자리표시자 잔존 — 초안을 복사해 쓰다가 OOO, ○○○, 홍길동, [작성] 같은 표현이 남는 사례가 가장 흔합니다.
  • 파일 형식 불일치 — .hwp로 저장했거나, 다른 프로그램에서 만든 ZIP이라 mimetype이 빠지면 접수 시스템이 열지 못합니다.

글자 수를 셀 때 알아야 할 것

이 도구는 본문 XML의 모든 텍스트를 합쳐 공백 포함과 공백 제외 두 가지로 셉니다. 표 안의 글자도 포함되고, 줄바꿈 문자와 그림은 글자로 세지 않습니다. 머리말·꼬리말과 각주는 본문 섹션 XML에 함께 들어 있어 합산됩니다. 반면 Preview/PrvText.txt에 들어 있는 미리보기 텍스트는 세지 않습니다.

공모전마다 기준이 다르기 때문에 숫자 하나만 믿지 말고, 공고문에 적힌 기준(공백 포함 여부, 표 포함 여부)을 먼저 확인해야 합니다. 이 도구의 ‘글자 수 제한’에 공고 분량을 넣으면 초과 여부를 바로 알려주고, 초과했다면 몇 자를 줄여야 하는지 계산해 줍니다. 한글에서 분량을 줄일 때는 표 안의 서술을 문장으로 바꾸는 것이 가장 빠릅니다.

이미지 용량은 접수 시스템에서 자주 걸리는 항목입니다. BinData 합계가 10MB를 넘으면 그림을 줄이거나 JPG로 바꿔 다시 저장하는 편이 안전합니다. 표 개수가 양식과 다르면 한글에서 원본 양식을 열어 빈 표를 다시 붙여 넣고 내용만 옮기는 방식으로 복구하세요.

문단 수와 섹션 수는 문서가 정상적으로 만들어졌는지를 보여주는 지표입니다. 섹션이 0개라면 본문을 읽지 못한 것이므로 확장자와 저장 형식을 먼저 확인해야 하고, 문단 수가 원본보다 크게 적다면 일부 내용이 빠졌을 가능성이 있습니다. 여러 명이 나눠 작성한 문서를 합치는 과정에서 표 하나가 통째로 사라지는 일이 흔하기 때문에, 제출 전에 양식 원본과 같은 파일을 나란히 열어 두고 숫자를 비교하는 것이 가장 확실합니다.

서식을 채울 때는 빈 문서에 내용을 새로 쓰지 말고, 공고에서 받은 원본 파일을 열어 칸 안에 입력하는 방식이 안전합니다. 원본을 유지하면 표 구조와 머리글·바닥글이 그대로 남아 서식 요건을 건드릴 위험이 줄어듭니다. 글꼴이 지정된 공모전이라면 붙여넣기 후 ‘모양 없이 붙여넣기(Ctrl+Shift+V)’를 사용해 다른 문서의 서식이 섞이지 않게 하세요.

HWPX와 HWP, 무엇이 다른가

두 형식은 겉보기에 비슷하지만 속이 전혀 다릅니다. .hwp는 한글의 독자 바이너리 형식이고, .hwpx는 국제 표준(OWPML)에 맞춰 문서를 XML 여러 개로 나눠 담은 개방형 형식입니다. 그래서 .hwpx는 압축을 풀어 내용을 직접 읽을 수 있지만, .hwp는 전용 프로그램 없이는 해석하기 어렵습니다. 공공기관 제출에서 .hwpx를 요구하는 곳이 늘어난 이유도 이 개방성 때문입니다.

한글 문서 형식 비교
구분.hwp.hwpx
내부 구조독자 바이너리XML + ZIP(OWPML)
내용 확인한글 필요압축을 풀면 텍스트 확인 가능
이 점검기지원 안 함지원
호환성한글 2010 이전도 열림한글 2014 이상
제출 요구기관에 따라 혼재공공·공모전에서 증가

제출처가 .hwpx를 요구하는데 .hwp로 저장해 두면 접수 단계에서 걸릴 수 있고, 반대로 .hwp만 받는 곳에 .hwpx를 올리면 담당자가 열지 못합니다. 공고문의 ‘제출 형식’ 항목을 먼저 확인하고, 변환한 뒤에는 표 너비와 글꼴이 달라지지 않았는지 출력 미리보기로 확인하세요.

공모전 글자 수 기준, 공고문에서 확인할 세 가지

“2,000자 이내”라는 문장만 보고 세면 기준이 어긋나기 쉽습니다. 공고문에서 아래 세 가지를 먼저 확인하세요.

  • 공백 포함인지, 제외인지 — 같은 문서라도 공백 포함 기준이 15~20% 더 많게 나옵니다. 이 점검기는 두 값을 함께 보여주므로 공고 기준을 고르기만 하면 됩니다.
  • 표 안의 글자가 포함되는지 — 대부분 포함하지만, 별도 서식으로 분리하는 공모전도 있습니다. 표가 많은 문서라면 차이가 수백 자까지 벌어집니다.
  • 제목·목차·참고문헌 포함 여부 — 본문만 세라고 명시한 경우에는 제목과 목차를 뺀 값을 따로 계산해야 합니다.

기준이 애매하다면 가장 엄격한 기준으로 맞추는 것이 안전합니다. 공백 포함 기준으로도 제한 이내라면 어떤 해석에도 걸리지 않습니다. 이 점검기에서 ‘글자 수 기준’을 ‘공백 포함’으로 바꿔 한 번 더 확인해 보세요.

자주 겪는 문제와 해결

  • “압축 파일이 손상되었습니다” — 파일이 이메일 첨부 과정에서 잘렸거나, 저장 중 오류가 난 경우입니다. 한글에서 다시 저장한 뒤 재시도하세요.
  • “ZIP 중앙 디렉터리를 찾지 못했습니다” — .hwp이거나 .pdf·.docx를 확장자만 바꾼 경우입니다. 확장자를 바꾸는 것으로는 형식이 바뀌지 않습니다.
  • 글자 수가 한글 화면과 다름 — 한글은 커서 기준으로 세고, 이 도구는 문서 전체를 셉니다. 머리말·꼬리말·각주·표 안 문단이 모두 포함되기 때문에 조금 많게 나오는 것이 정상입니다.
  • 이미지 용량이 큼 — BinData 합계가 수십 MB면 접수 시스템이 거부할 수 있습니다. 그림을 1,000px 안팎으로 줄이고 JPG로 다시 저장하면 대부분 해결됩니다.

제출 직전 3분 체크리스트

  1. 한글에서 다른 이름으로 저장 → .hwpx로 저장했는지 확인합니다(구형 .hwp는 점검 불가).
  2. 이 페이지에 파일을 올려 글자 수 제한과 표 개수를 확인합니다.
  3. 자리표시자 경고가 뜨면 한글에서 해당 문구를 찾아 실제 내용으로 바꿉니다(찾기: Ctrl+F).
  4. 파일명을 공고가 요구하는 형식(예: 이름_제안서.hwpx)으로 바꿉니다.
  5. 접수 시스템에 올린 뒤 미리보기가 열리는지 마지막으로 확인합니다.

자주 묻는 질문

업로드한 문서가 서버로 전송되나요?

아니요. 이 페이지는 파일을 읽어 브라우저 메모리에서만 분석합니다. 외부 API 호출도, 전송도 없으며 페이지를 닫으면 파일 내용은 사라집니다. 인터넷을 끊고 페이지를 열어 두었다면 점검이 그대로 동작합니다.

글자 수는 어떻게 세나요?

본문 XML의 텍스트 노드를 모두 합쳐 공백 포함과 공백 제외 두 가지로 셉니다. 표 안의 글자도 포함되고, 줄바꿈 문자와 그림은 글자로 세지 않습니다. 공모전마다 기준이 다르므로 공고에 적힌 기준(공백 포함 여부)을 먼저 확인하세요.

.hwp 파일도 점검할 수 있나요?

아니요. 이 도구는 .hwpx(OWPML, ZIP 구조)만 지원합니다. 구형 .hwp는 압축 구조가 달라 인식되지 않으니 한글에서 다른 이름으로 저장 → .hwpx를 선택해 변환한 뒤 점검하세요. 변환 후에는 글꼴·표 너비가 조금 달라질 수 있으므로 출력 미리보기로 한 번 더 확인하는 것이 좋습니다.

왜 공모전 제출 전에 규격을 점검해야 하나요?

공모전은 서식(지정 양식)·분량(글자 수)·파일 형식 요건을 어기면 심사 전에 반려되는 경우가 있습니다. 글자 수 초과, 표 누락, OOO 같은 자리표시자 잔존, 확장자 불일치가 대표적인 반려 사유입니다. 제출 직전에 이 네 가지를 확인하는 것만으로 위험을 크게 줄일 수 있습니다.

점검 결과의 표·문단 수가 한글 화면과 다른 이유는 무엇인가요?

한글 화면은 편집 단위로 보여주지만, 이 도구는 XML 구조를 그대로 셉니다. 표 안의 문단도 문단으로 세고, 표를 감싸는 문단도 따로 잡히기 때문에 숫자가 조금 클 수 있습니다. 절대값보다 양식 원본과 비교한 차이를 보는 것이 중요합니다.

여러 파일을 한 번에 점검할 수 있나요?

현재는 한 번에 한 파일씩 점검합니다. 파일을 바꾸려면 선택한 파일 옆의 ✕ 버튼으로 지우고 새 파일을 올리면 됩니다. 여러 지원서를 비교할 때는 각 파일의 결과를 ‘결과 복사’ 버튼으로 복사해 표로 정리하면 편리합니다.

점검 기록이 어디에 저장되나요?

어디에도 저장되지 않습니다. 서버 전송도, 브라우저 저장소 기록도 남기지 않으며 페이지를 닫으면 즉시 사라집니다. 결과를 보관하려면 화면의 ‘결과 복사’ 버튼으로 직접 복사해 두세요.
